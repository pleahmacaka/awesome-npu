データについて

Commercial NPUs and AI inference accelerators, from MCU-class parts to datacenter cards.

Data is compiled from vendor pages and public reporting (2025–2026) and may lag product revisions. Compute figures are vendor-stated peak TOPS at INT8 unless noted; datacenter parts often publish throughput/memory specs instead of a single TOPS number, shown as -. Prices are listed only where officially disclosed. Sorted by compute, ascending.

⚠ marks parts that are not standalone products · SoC-integrated or IP that must be built into a host system.

The Memory column shows dedicated on-board/on-chip memory where a part carries its own; shared (host) or unified means it uses the host system's RAM instead. This matters for LLM/VLM work, where model size is bound by available memory.

Notes on Pi compatibility

Coral hasn't seen meaningful driver/runtime updates in years; expect friction with recent Python/OS releases. Still fine for TFLite vision.

NCS2 is discontinued (EOL); usable only on legacy OpenVINO. Buy only from remaining stock.

Multi-accelerator rigs (e.g. several Coral + Hailo behind a PCIe switch on Pi 5) work but need driver/overlay hacks and offer limited multi-chip software support.

Mobilint / Rebellions / FuriosaAI make no M.2 or USB part and cannot attach to a Pi.

Compilers & IR

Vendor-neutral compiler stacks that lower a model through an intermediate representation to hardware-specific code.

  • Apache TVM - Deep-learning compiler with auto-scheduling; microTVM targets MCUs/NPUs.
  • IREE - MLIR-based compiler + runtime for edge to datacenter.
  • MLIR - LLVM compiler infrastructure underlying many NPU stacks.
  • Glow - Meta's ML graph compiler for accelerators.
  • XLA - Operation-fusion compiler (TF/JAX), influences edge compiler design.
  • OpenXLA / StableHLO - Portable HLO dialect across compilers.

Runtimes & inference engines

Cross-vendor runtimes that dispatch to CPU/GPU/NPU back-ends.

  • ONNX Runtime - Execution-provider interface binds graphs to NPU back-ends (NNAPI, OpenVINO, TensorRT, QNN).
  • ExecuTorch - PyTorch Edge runtime for mobile/embedded/MCU with NPU delegation.
  • TensorFlow Lite / LiteRT - On-device runtime; NNAPI/GPU/NPU delegates.
  • LiteRT-LM - LiteRT extension for on-device LLMs.
  • NCNN - Tencent's mobile-first inference framework.
  • MNN - Alibaba's lightweight edge inference engine.
  • MACE - Xiaomi's mobile NN accelerator.
  • TNN - Tencent cross-platform inference framework.
  • NNAPI - Android's neural networks hardware abstraction (legacy; superseded by LiteRT delegates).
  • QNN (Qualcomm AI Engine Direct) - Low-level Hexagon NPU access.

LLM on edge

Running local language models on constrained hardware.

  • llama.cpp - CPU-first GGUF inference, minimal setup.
  • Ollama - Local LLM runner built on llama.cpp.
  • MLC LLM - TVM-based LLM deployment across GPU/NPU/mobile.
  • torchchat - PyTorch local LLM inference (server/desktop/mobile).

Model optimization (quantization / pruning)

The step that makes models fit an NPU · usually INT8 quantization.

  • Neural Network Compression Framework (NNCF) - Intel quantization/pruning for OpenVINO.
  • PyTorch Quantization - Native PTQ/QAT (eager + FX + export).
  • TensorFlow Model Optimization Toolkit - Quantization, pruning, clustering.
  • ONNX Runtime quantization - Post-training INT8 for ONNX.
  • AIMET - Qualcomm's model-efficiency toolkit (quant + compression).
  • Brevitas - AMD/Xilinx quantization-aware training in PyTorch.
